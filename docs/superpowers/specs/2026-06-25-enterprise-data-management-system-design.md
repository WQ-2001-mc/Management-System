# NEXUS 企业数据管理系统设计规格

日期：2026-06-25  
状态：已确认视觉方向，待实施

## 1. 产品目标

NEXUS 是面向中小型及成长型企业的一体化数据管理平台。系统把组织、客户、项目、合同、文件、审批和经营数据放入统一工作台，减少跨表格、聊天工具和零散文件之间的信息割裂。

首版需要同时满足三个目标：

1. 作为可直接运行的完整开源项目，而不是静态后台模板。
2. 具备企业系统需要的权限、安全、审计、数据导入导出和部署能力。
3. 保留清晰的领域边界，方便未来增加采购、财务、CRM 销售漏斗和自动化流程等模块。

## 2. 用户角色

- 超级管理员：管理系统配置、租户、角色、权限及全部数据。
- 企业管理员：管理本企业的组织、成员、业务配置和审计记录。
- 部门负责人：查看本部门经营数据，管理项目、客户、合同和审批。
- 普通员工：处理被授权的客户、项目、文件、任务和审批。
- 审计查看者：只读访问经营报表、合同记录和操作日志。

所有角色均通过 RBAC 权限控制。数据查询同时受企业、部门、负责人和资源授权范围约束。

## 3. 功能范围

### 3.1 工作台

- 营业收入、回款、在执行项目、新增客户等关键指标。
- 营收与回款趋势、目标达成、客户分布和业务健康度。
- 风险预警、待办审批、近期动态和项目合同运营表。
- 用户可见数据必须根据其权限范围聚合。

### 3.2 组织与人员

- 企业、部门树、岗位、员工档案和成员状态。
- 员工邀请、启用、停用、部门调动和角色分配。
- 部门负责人及数据权限范围配置。

### 3.3 客户中心

- 客户档案、联系人、行业、地区、等级、负责人和跟进状态。
- 跟进记录、关联项目、关联合同和附件。
- 搜索、组合筛选、分页、批量操作、CSV 导入与导出。

### 3.4 项目交付

- 项目基本资料、负责人、成员、客户、预算、日期和进度。
- 项目阶段、里程碑、任务、风险和动态记录。
- 看板、列表和详情视图。

### 3.5 合同与回款

- 合同编号、客户、项目、金额、状态、签署日期和到期日期。
- 回款计划、回款记录、逾期提醒和合同附件。
- 合同审批、状态流转和金额汇总。

### 3.6 文件资产

- 文件上传、目录、标签、业务资源关联和访问权限。
- 文件元数据、下载记录及软删除。
- 首版使用本地对象存储接口，支持通过环境变量切换 S3 兼容服务。

### 3.7 审批流程

- 合同、采购申请、费用报销和通用审批单。
- 提交、同意、驳回、撤回和审批意见。
- 首版采用可配置的顺序审批，复杂 BPMN 流程不纳入本轮。

### 3.8 系统管理

- 用户、角色、权限、菜单、数据字典和系统参数。
- 通知中心、登录日志、操作日志和审计检索。
- 企业资料、外观、编号规则和安全设置。

## 4. 技术路线评估

### 方案 A：Next.js 模块化单体（采用）

React、TypeScript、Next.js、Ant Design、Prisma 和 PostgreSQL 放在同一仓库，通过领域模块组织服务端与前端代码。

优点：交付速度快、类型贯通、部署简单、适合首版完整产品；后续仍可拆分服务。  
代价：需要严格维持模块边界，避免业务逻辑散落在页面和接口中。

### 方案 B：React + Spring Boot 前后端分离

适合大型 Java 团队和复杂集成，但本轮会把较多时间投入脚手架、DTO 和部署编排，降低可见功能完成度。

### 方案 C：React + NestJS 前后端分离

保持 TypeScript 技术栈并具有清晰服务结构，但双应用开发和部署复杂度高于当前需求。

最终选择方案 A。系统采用模块化单体架构；对外接口、领域服务和存储层保持独立，为未来拆分留出边界。

## 5. 技术架构

- Web：Next.js App Router、React、TypeScript。
- UI：Ant Design、CSS Variables、Lucide 图标。
- 图表：Apache ECharts。
- 数据获取：服务端组件优先；客户端交互使用 TanStack Query。
- 表单与校验：React Hook Form、Zod。
- 数据库：PostgreSQL、Prisma ORM。
- 鉴权：Auth.js 凭据登录、数据库会话、Argon2 密码哈希。
- 文件：统一 Storage Adapter，本地开发落盘，生产支持 S3 兼容对象存储。
- 测试：Vitest、Testing Library、Playwright。
- 工程：ESLint、Prettier、Husky、lint-staged、GitHub Actions。
- 部署：Docker Compose 启动 Web 与 PostgreSQL；提供健康检查和种子数据。

## 6. 代码结构

```text
src/
  app/                 路由、布局、页面和 API 入口
  components/          通用 UI 与业务组件
  features/            按领域组织的前端功能
  server/
    modules/           组织、客户、项目、合同等领域模块
    auth/              身份认证和授权
    db/                Prisma 客户端与事务
    storage/           文件存储适配器
    audit/             审计记录
  lib/                 通用工具、校验、常量
prisma/
  schema.prisma
  seed.ts
tests/
  e2e/
```

每个领域模块包含 schema、repository、service、permission 和 tests。路由层只负责输入输出，不直接包含业务规则。

## 7. 核心数据模型

- Tenant、Department、Position、User、EmployeeProfile。
- Role、Permission、UserRole、RolePermission。
- Customer、Contact、CustomerFollowUp。
- Project、ProjectMember、Milestone、Task、ProjectRisk。
- Contract、PaymentPlan、PaymentRecord。
- FileAsset、FileRelation。
- ApprovalDefinition、ApprovalRequest、ApprovalStep、ApprovalAction。
- Notification、AuditLog、LoginLog、SystemSetting。

所有核心业务表包含 `tenantId`、创建人、更新人、创建时间、更新时间；需要保留历史的数据使用软删除字段。

金额统一使用数据库 Decimal，时间统一以 UTC 存储并在界面按用户时区显示。

## 8. 权限与安全

- 菜单权限、操作权限和数据范围三层授权。
- 服务端每个受保护入口必须执行会话与权限检查，不能只隐藏前端按钮。
- 资源查询默认强制附加 `tenantId` 条件，防止跨企业访问。
- 登录限速、密码策略、会话过期和安全 Cookie。
- Zod 校验所有写入请求；数据库层使用参数化查询。
- 重要操作写入不可由普通用户修改的审计日志。
- 上传文件校验大小、扩展名和 MIME 类型，并使用随机存储键。
- `.env`、密钥、上传文件和数据库文件不得提交到 Git。

## 9. 视觉与交互

最终视觉基准存放于 `docs/design/nexus-dashboard-reference.png`。

- 深石墨色窄侧栏，暖白主画布，电光靛蓝作为主色。
- 非对称、编辑式仪表盘层级，避免等尺寸卡片铺满页面。
- 8px 间距体系，10–12px 圆角，轻分隔线，有限阴影。
- 默认中文界面，桌面优先，并适配平板与移动端。
- 支持明暗主题、侧栏折叠、全局搜索和快捷新建。
- 表格支持列配置、筛选、排序、分页和批量操作。
- 加载、空状态、错误、无权限、删除确认和保存反馈均有明确状态。
- 动效控制在 150–240ms，并尊重 `prefers-reduced-motion`。

## 10. 数据流与错误处理

1. 页面或交互组件提交经过 Zod 校验的数据。
2. API/Server Action 验证会话、权限和租户范围。
3. 领域服务执行规则并通过 repository 访问数据库。
4. 写操作在事务中同步写入业务数据、通知和审计记录。
5. 客户端刷新相关查询并显示成功或错误反馈。

错误分为校验错误、未认证、无权限、资源不存在、业务冲突和系统错误。界面提供可理解的中文信息；服务端日志保留错误上下文，但不向客户端泄露敏感细节。

## 11. 测试与质量门槛

- 单元测试：权限判断、金额计算、状态流转和校验规则。
- 集成测试：数据库 repository、领域服务和审计写入。
- 组件测试：表单、表格筛选、状态反馈和权限显隐。
- E2E：登录、创建客户、创建项目、创建合同、登记回款、提交审批、角色授权。
- CI 必须通过格式检查、Lint、TypeScript、单元测试、构建和关键 E2E。
- 种子数据提供管理员及不同角色账户，README 明确登录方式。

## 12. 首轮交付标准

- 可通过 Docker Compose 一条命令启动。
- 有完整 README、环境变量示例、架构说明和演示账户。
- 核心模块具备真实数据库 CRUD，不使用仅存于浏览器的模拟数据。
- 工作台、客户、项目、合同、组织、审批、系统管理形成可导航闭环。
- RBAC、租户隔离、审计日志和基本文件上传可用。
- 自动化测试及 GitHub Actions 可运行。
- 提交历史清晰，并推送至 `HXB-1997/Management-System` 的主分支。

## 13. 本轮明确不做

- 微服务、消息队列和 Kubernetes。
- 完整财务会计、薪酬、进销存及复杂 BPMN 引擎。
- 短信、企业微信、钉钉等外部生产集成。
- 多语言内容维护界面。

这些能力保留扩展点，但不以牺牲首版完整性为代价提前实现。
